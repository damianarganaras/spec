## 8. Unknowns / límites

- **Arquetipos**: `stats` y `stats failures` no exponen etiqueta de arquetipo
  (fix de conformidad / feature con delta / cambio de adapter o contrato compartido). Las sesiones
  sólo traen `title`, `agent`, `model`, `cost`, `tokens`. No se extrapola conteo por arquetipo; los
  agregados disponibles son los de §5. Tampoco hay muestras etiquetadas de recuperación de memoria
  ni de continuidad entre sesiones: quedan como `unknown`.
- **Wall time**: no existe métrica de tiempo de cómputo. `timeCreated`/`timeUpdated` son marcas de
  la sesión (su diferencia es el lapso de vida, no el wall de la corrida); no se reporta wall.
- **Errores de sesión**: el JSON de `stats` no incluye `errors`. `stats failures` mide tool parts
  fallidos con otra unidad y otro universo; no equivale a "sesiones con error".
- **Semántica de cache**: `cacheRead`/`cacheWrite` se registran crudos. No hay semántica de
  proveedor validada (si `cacheRead` incluye o no el prompt total, ni unidad de `cacheWrite`);
  por eso no se derivan ratios de acierto ni ahorro. En alcance proyecto `cacheWrite=0`, en global
  no.
- **USD**: se reporta el campo `cost` tal como lo entrega cada sesión; no se recalcula por tarifa.
- **Alcance global**: `--all` mezcla directorios de otros proyectos (p. ej. sesiones fuera de este
  repo). El baseline comparable es el de alcance proyecto.
- **Snapshot temporal**: la medición se tomó con una sesión activa; los totales pueden variar en
  una re-corrida del mismo commit.
- **`pluginVersion`**: `discovery --check` no lo emite (schemaVersion 2).
- **Métricas de host**: no se midieron CPU, RAM ni I/O durante `npm test`; sólo se registra el
  host declarado. Otra máquina puede diferir.
- **Deriva de artefactos locales**: `.ancletorc` (0.40.0) y `machine-env` (0.39.1) no coinciden con
  el CLI 0.43.0; un `ancleto upgrade` cambiaría los artefactos locales.
